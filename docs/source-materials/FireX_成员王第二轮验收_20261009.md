## 2. 本次复核发现的修正点

### A. 省级地图接口与代码不能混用

原包引用的 GeoJSON.CN 是数据分发与转换服务，不应把该接口本身写成天地图官方 API。其网页说明数据源来自天地图，页面列出了 CGCS2000/EPSG:4490。

两种页面需要分开：
- [原始文件页面](https://geojson.cn/data/file/Tiandi_China)：列出2025-09数据更新时间、审图号和九位 gb。
- [分级接口说明](https://geojson.cn/data/atlas/tiandi)：列出六位 code、九位 gb，以及0.3.0版本日志（2025-12-16）。

项目电厂省份代码是六位，例如贵州520000；九位 gb 的贵州示例是156520000，直接关联会失败。优先使用接口的六位 code；只有确认是中国156前缀的九位 gb，才取末六位，不能任意截取。

本次请求默认 GeoJSON、固定0.3.0版本、TopoJSON和元数据接口，均未取得有效几何（502或超时）。这证明的是“本次尚未成功下载”，不能据此认定接口永久失效或要求校园网。

**开发处理：** 底图作为可替换数据资源；取得后记录实际版本、CRS和字段并做地图检查。若当前仍无法取得，可先开发省份列表、电厂详情及模型查看器，明确全国地图待补；不能用伪造边界充数，也不能把空地图称作地图验收完成。

### B. 织金的场景编号与电厂编号需要正式关联

| 含义 | 使用值 |
|---|---|
| 这批地图电厂编号 | GEM_COAL_ZHIJIN |
| 项目内部电厂键 | fx_chnenergy_zhijin_babu_pilot |
| 现有模型场景编号 | zhijin_pilot |
| 模型版本 | v4 |
| 队友原场景标记 | ZHIJIN_16KM2_TRIAL（保留在原始文件） |

GEM_COAL_ZHIJIN 等名称是这批交付自定义的项目ID，不是已取得的 GEM 官方数据库稳定ID；source_id 写“GEM wiki project page”也不是机器级来源记录编号。开发仍可将这些值作为项目内稳定键，后续接全国数据时保留映射，不要冒充外部原生ID。

GEM 来源页列出织金位置105.818927,26.832824和一期两台660 MW运行机组，能支持本批1320 MW及八步位置的初步身份匹配。[GEM织金项目页](https://www.gem.wiki/Guodian_Zhijin_power_station)

该点与旧模型包的OSM厂界内代表点相距约119.3 m。两者代表点定义不同；这个距离既不是模型精度，也不能直接当作纠偏向量。开发应以地图新点作入口、通过ID打开原有局部模型，保持模型坐标；不可为了对齐点位单独平移模型。

本次另行提供了适配数据，保留原ZIP，不覆盖队友原文件或原模型manifest。

### C. 向家坝容量可以采用6400 MW，但差异解释仍待核查

[三峡集团2025-11-10报道](https://www.ctg.com.cn/sxjt/xwzx55/zhxw23/2025111109411779818/index.html)明确写总装机640万千瓦，因此6400 MW有国内官方依据。

GEM当前来源页仍列7750 MW，并列出“8×800 MW；3×450 MW”。因此仅凭网页新旧日期不能把7750 MW定性为历史容量，也不能证明2026年实测运行容量已改变。两个数字是否涉及统计对象、附属设施或数据错误，仍需核查。[GEM向家坝项目页](https://www.gem.wiki/Xiangjiaba_hydroelectric_plant)

本次适配数据保留6400 MW用于展示，明确口径为“2025年官方报道的电站总装机容量”；将7750 MW作为来源差异保留。原包所引2025-12-30采购链接本次超时，未独立复核其日期及正文。

### D. 来源字段与遥感表还有两个小问题

1. 织金 official_case_source 指向 OpenInfraMap 首页，该站不是该厂的官方工程资料，也不能支持本厂参数。适配数据移入 community_map_url；用已有国家能源集团织金官方照片页作为官方场景参考，但照片不能证明所有容量或尺寸。
2. SRTM表写“全球”过于笼统，其任务覆盖约北纬60°至南纬56°，不是全地球覆盖。中国本项目区域在覆盖纬度内；该修改不阻碍织金开发。[USGS覆盖说明](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-digital-elevation-shuttle-radar-topography-mission-srtm-non)
3. 标准SRTM产品的2000年获取时间与EGM96说明，不能直接证明我们当前Mapzen混合地形瓦片的逐像元年代和垂直基准；模型仍保留这些未知项。
4. 本次通过GEM来源页检索结果核对7个电厂点位及主要容量信息，不等于完成独立影像定位、行政边界叠加或现场精度验证。未下载完整GEM原始发布库，不能把样例称为直接从某版全量数据库导出的已验证子集。

## 3. 现在开发到哪一步合适

**第一阶段：先打通省份→电厂→织金三维场景。**

- 全国省级底图资源取得后显示省份；点省份按related_province_codes筛选样例电厂。
- 跨省电厂可在两省列表出现，全国数量按plant_id去重。
- 其他省份显示“暂无样例数据”，不能解释为当地没有电厂。
- 点电厂展示名称、技术类型、容量及来源；只有织金提供三维入口。
- 加载真实v4 GLB，支持旋转、缩放、场景取景、对象选择、返回地图/列表。
- 设施状态显示“试建”“身份未核实”等原有证据标签；未接入火情显示“尚未接入”，不显示“安全”。

**第二阶段：前端闭环成功后，做演示火区与地图告警。**

在局部地形上显示火区范围与变化，支持暂停、重置；显式标为演示。简单动画或自定蔓延规则只能验证交互与数据联动，不能宣称已复现有依据的火势预测。虚拟无人机、图像输出、算法输入与估计火情再逐项接入；仿真真值与识别估计必须分开。

**可以后补：** 电网分组视图、应急流程、风险阈值、全国电厂扩充、高分纹理、真实天气/燃料数据。队友B当前可以暂缓，不影响第一阶段；其规则资料需在接入真实风险分级和应急方案前补齐。
