# 双江口告警直达三维与火焰剖面

首页红标表示厂站收到火焰观测。告警卡「查看三维火情」跳到该条观测绑定的场景和运行；「电厂详情」保留作资料入口。三维页会自动连接，仅在场景、厂站、版本、坐标系和地形资产相符时绘制新的火焰剖面。首个有效剖面自动取景，后续更新不抢占相机；可手动点击「聚焦火焰」。

剖面由上传的同帧图像、相机内参和已转换到 GLB 局部米制的位姿计算。只处理最高置信度火焰框；以其中主要亮橙区域估计可见边缘，以靠下的像素射线和已有地形的交点近似深度。贴图来自同一帧的火焰像素，背景在贴图中透明。前端显示的是随帧变化的单视角几何，落点未验收、深度未测、火焰体积未知。地形与设施还是已有 GLB，不做地理配准，与 `patches` 的贴地图层分开。

## 本机联调

1. 用原来的 `FIREX_BACKEND_DATA_DIR` 和 `FIREX_MONITORED_RUN_IDS` 重启本轮 FastAPI，保留现场已验证的 YOLO 参数（本轮可用 `FIREX_YOLO_IMGSZ=1280`、`FIREX_YOLO_CONF=0.25`）。前端继续通过其代理连接同一实例。原 Unity 上传接口与坐标无需修改。
2. 开着首页，让 Unity 对同一个 run 上传一帧新图，使用新 `capture_id` 和严格递增的 `simulation_time_s`。有火、火焰下沿清楚、未画框的 PNG 更适合检查剖面。校对上传返回的 ID、`completed`、`state.revision` 和 `evidence_capture_ids`。
3. 点击「查看三维火情」。确认地址带同一个 `run_id`，状态里的 `flame.capture_id` 是这张图，画面显示「单视角火焰剖面」。已有 2D 告警但 `flame=null` 时保留二维告警，检查该帧原图与相机参数。
4. 不刷新，再传同一位置、不同形状的第二张有火帧。验收新 `revision`、新证据 ID、几何顶点实际变化，并确认不重载基础 GLB。再传观测时间更晚的无火帧，前者剖面消失，显示「本帧未检出火焰」。停止输入超过有效窗口，旧剖面不得冒充现时观测。
5. 记录 Unity 上传、后端推理/剖面计算、浏览器显示各自的时延。此处验证的是随抓拍更新；未经持续测试不标为实时高帧率。

## 回放验收结果

在独立 SQLite、Vite 和 Chromium WebGL 会话中，使用两张历史 Unity 原图、各自位姿和已记录的 YOLO 框重新计算剖面。两张有火帧均生成 64 个顶点，顶点坐标和浏览器画面随帧改变；再送入无火测试帧与推进过期时钟，均只清除剖面，基础 GLB 全程请求一次。该验收覆盖接口与渲染，不包含重新运行 YOLO 或测量局域网端到端延迟；现场按上面的步骤复测。

## 完整动态场景的下一批输入与验收

- **环境几何**：同一局部厂区采两批有重叠、相机位置有平移的无火原图，每批先取 4–6 视角。保留原图、各自的位姿/内参、批次 ID 与场景版本，不向 VGGT 输入 GLB 真值作为结果。跑现有 D1 的全视图点图流程；把局部重建和已知场景做尺度与坐标对齐，记录留出验证点误差、重叠区误差、新覆盖和耗时。两批各生成一份带证据帧的真实点云，在不重载底座的情况下替换/补充局部层，才通过环境动态建模。
- **火焰粗体积**：每组用 2–3 个不同位置的相机在同一 Unity 仿真步采集，至少两个仿真步；保留各相机原图、位姿/内参、`camera_id`、组 ID 和仿真时间。火焰掩膜如可独立导出，作为验收对照。只有可从多视角得到对应外包络并与留出视角核对后，才称为粗三维火焰重建。
