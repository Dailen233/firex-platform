# 双江口输电走廊与多视角火焰试验

## 基础场景、接线关系和近端走廊

现有基础模型可用于无人机巡检和联调。发电厂房、GIS 开关楼、升压区与运维区是模拟设施；公开资料说明实际主厂房为地下厂房。没有竣工总图、可核对的控制点和厂房几何时，不把地面示意厂房补成实物复刻。

「电力网络」显示两类信息：

| 信息 | 范围 | 数据依据 |
| --- | --- | --- |
| 公开接线关系 | 双江口 500 kV 开关站 → 两回 500 kV 线路 → 阿坝 1000 kV 变电站的 500 kV 间隔；单回约 106 km | [送出工程环评公示](https://sthjt.sc.gov.cn/sthjt/c103939/2025/6/5/281ff75ffe3646d782ebd807ed52b387.shtml)、[核准报道](https://epaper.ceic.com/pad/content/202502/12/content_11215.html) |
| 近端巡检走廊 | 约 4.5 km，模拟升压台地门架加 13 基地形塔，13 跨，每跨两回三相导线 | 当前 GLB 局部 XZ 帧的仿真布局。塔脚取地形三角面高度，弧垂和塔身只用于展示。路线、塔高、塔型和共塔方式均不表示现实工程。 |

打开 `/#/scene/sjk_hydropower_sim_v0_1` →「电力网络」→「显示仿真塔线」。可在「站端取景」和「走廊全景」之间切换，也可关掉图层。该图层只绑定 `hydro-sim-v0.1-local` 的当前 GLB 哈希，基础模型、地形、run 与坐标契约保持原样。接线关系可独立查看，站端塔线浏览无需连接 FastAPI。两层都不表示潮流、带电状态或受火影响判断。

页脚的「局部坐标（米）· 未做地理配准」表示：当前 Unity 与 GLB 的局部轴映射可用于抓拍对齐，模型的真实经纬度、北向与高程基准还缺少独立控制点核实。接入实测线路之前，先用带 CRS 和高程基准的控制点拟合并留点验算；再导入有来源的线位或塔位。不能把公开 DSM 或周边地图线直接贴到此局部场景。

验证：前端 36 项数据检查通过，合成线路的导线采样点与实际 GLB 地表均分离（本版最小约 10.49 m，仅供几何渲染核对），构建通过。桌面 Chromium WebGL 检查涵盖站端和全景可见、图层开关与切换场景。另用历史 Unity 原图及已记录的检测框回放：开启塔线后，连续观测仍更新火焰剖面；未检出和过期分别清除剖面，塔线保留，GLB 只加载一次。该回放不测 YOLO 推理和局域网延迟。

## 离线火焰外包络

同一组两张图以相同颜色规则提取火焰像素，只用这两张图的掩膜和位姿保留同时可见的 4 m 体素。第三台相机完全不参与区域选择和重建，只对体素外表面作独立回投。IoU 表示预测轮廓和留出图像颜色掩膜交集与并集的比值；颜色掩膜也会漏掉受烟遮挡的火焰，不是人工标注或三维真值。

| Unity 仿真时刻 | 体素数 | 第三视角重合 IoU | 覆盖参考掩膜 | 预测面积 / 参考面积 |
| --- | ---: | ---: | ---: | ---: |
| 1800 s | 40,738 | 41.0% | 97.2% | 2.34× |
| 3600 s | 55,145 | 20.2% | 94.4% | 4.61× |

两组候选体积覆盖了大部分参考掩膜，但多出了大片区域，第二组尤其明显。先保留离线结果，不替换线上单视角剖面，也不把体素数当成物理火焰体积。该试验没有地形裁剪、地理位置核准或实时性能验收。原 ZIP 只声明场景、版本、局部帧，未携带 GLB 的 SHA-256；帧与包的哈希保存在输出中。

将队友原包放在本地（不入库），使用有 NumPy、Pillow 和 SciPy 的 Python 运行：

```bash
"$HOME/vggt/vggt-env/bin/python" experiments/c2-camera-geometry/reconstruct_multiview_flame.py \
  data/multiview_capture.zip
```

输出在 `runtime-data/e3-multiview-flame/`：逐组体素中心 `.ply`、第三视角对照图（绿=重合，橙=仅参考，蓝=仅预测）、汇总 `summary.json`。

下一轮先让 Unity 对同一仿真步额外留出一台相机（每组 3 台重建、1 台检验），导出逐相机的原图、位姿和独立火焰掩膜，优先把烟与地形从掩膜中分开；用独立时刻检查误差再决定是否接入实时分组更新。环境几何另用两批有重叠、相机有平移的无火影像，在升压区周边先做一个可替换的局部重建层；复用当前基础场景，避免把每帧重建整块地形当成目标。

## 地形裁剪对照与新采集包验收

对同一批旧的 2+1 机位采集，用同样的颜色掩膜、4 m 体素、留出相机和像素计分重跑。唯一变化是在回投前排除中心低于当前 GLB 地形三角面的体素；留出相机没有参与重建、裁剪或选参数。

| 仿真时刻 | 移除体素数 | 留出视角 IoU | 留出掩膜覆盖率 | 预测面积 / 参考面积 |
| --- | ---: | ---: | ---: | ---: |
| 1800 s | 7,139 | 41.0% → 44.9% | 97.2% → 93.3% | 2.34× → 2.01× |
| 3600 s | 12,140 | 20.2% → 30.6% | 94.4% → 90.7% | 4.61× → 2.88× |

地形先验减少了明显的过包络，也让一部分参考掩膜不再被覆盖。旧样本仍使用颜色代理，没有独立火焰掩膜或真实体积；这里的 IoU 用于诊断，不能当作定位精度。裁剪只检查体素中心，不做相机遮挡消除，不改变在线剖面。原始数值见 evidence/sjk-multiview-terrain-ab.json。

在旧包上复现时可分别运行默认选项和地形裁剪选项，把产物写入不同目录：

    "$HOME/vggt/vggt-env/bin/python" experiments/c2-camera-geometry/reconstruct_multiview_flame.py \
      data/multiview_capture.zip --terrain-clip --out runtime-data/e3-multiview-terrain-clip

新采集继续使用原来的 ZIP / manifest.csv 格式，每个机位加一列 mask_file，指向与原始 PNG 同像素尺寸的黑白 PNG（火焰=255，背景和烟=0，若带透明通道则必须全不透明）。至少两个不同仿真时刻；每个时刻固定三个不同位置的 reconstruction 机位和一个不同位置的 validation 机位，所有图像、位姿、掩膜来自同一步。若元数据包含 glb_sha256，必须与版本匹配。不要裁图、缩图或把掩膜画到原图上。

    "$HOME/vggt/vggt-env/bin/python" experiments/c2-camera-geometry/reconstruct_multiview_flame.py \
      data/sjk_four_view_masks.zip --require-four-view-masks --terrain-clip \
      --out runtime-data/e3-multiview-four-view

合成测试覆盖了 3+1 机位、拒绝尺寸不匹配、地形裁剪，以及只移动留出掩膜时评分改变而 PLY 完全一致。运行：

    "$HOME/vggt/vggt-env/bin/python" -m unittest discover \
      -s experiments/c2-camera-geometry -p test_multiview_inputs.py

四机位接口已经准备；队友提供实际同步素材后，才做真实四机位对照。
