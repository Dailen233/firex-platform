# 场景加载与交互检查方法

本轮已有参考GLB可用于建立记录方法；不能把它的表现当成正式100km²精细模型的性能结论。

1. 记录场景ID、资产版本/SHA、模型字节数、贴图总字节、浏览器版本、设备/GPU、视口及运行模式。
2. 在首次冷加载和重复热加载分别记录：请求开始→模型下载完成→校验完成→解析完成→首次可见帧。没有Content-Length时显示阶段/已下载字节或不确定进度，不伪造总百分比。
3. 区分压缩传输大小、资源解压后的实际字节数、GLB文件字节数。缓存命中应写清，不能将热缓存耗时当作网络冷加载。
4. 记录全景取景、恢复默认视角、连续旋转/缩放1分钟是否有明显卡顿、控制台错误、上下文丢失、覆盖标记错位。没有量化工具就记录“人工观察”，不填推测FPS。
5. 390×844和768×1024为桌面浏览器模拟视口检查，分别检查控制栏、加载/失败提示和画布；真实手机性能另列未测。
6. 通过测试场景配置中的错误模型URL验证失败提示和重试；恢复正确配置后复测。不得损坏或删除原资产来造故障。
7. 路由离开/返回反复3次，检查画布与标记没有重复，viewer释放资源；长期GPU/内存测试另列，不能用3次切页宣称长期稳定。
8. 正式模型到手后再依据真实网格数、材质/贴图大小、视距和实测决定分块、LOD、压缩或简化；本轮不先装完整切片系统。
