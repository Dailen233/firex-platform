# CodeBuddy 首次接手提示词

将新仓库克隆到 `~/projects/firex-platform`，在CodeBuddy打开该目录。首次用Plan模式粘贴以下内容，先检查现有代码，不重建工程。

```text
你正在接手Fire-X前端R1/0.1.0。已有省级地图/省份列表→电厂详情→织金v4原始GLB→返回流程。请按软件工程模式工作。

先完整阅读README.md、docs/01-requirements.md、02-design.md、03-acceptance.md、05-development-plan.md和AGENTS.md，检查实际源码及package-lock.json。先不要新增业务功能，不重新搭建项目。

本次仅在我的Ubuntu本机复现并完成现存验收缺口：
1. 查看git status、Node/npm版本，保留用户修改。按锁文件npm ci，运行npm run test:data与npm run build。环境不足时先说明原因与最小修复方案，不直接升级系统或改变Python环境。
2. 启动开发服务，确认省份→织金详情→模型→返回两轮；四川6、云南4、全国7；空省份与其他六厂无模型状态正确。
3. 重点验证WebGL2。云验收浏览器GPU禁用，只实际验收Canvas2D兼容模式。确认本机采用的渲染模式；观察完整GLB地形、厂区、B01/CH01/CT-A点选和材质。兼容模式不算GPU路径通过。
4. 真实浏览器视口检查桌面、390×844、768×1024：无水平溢出、模型可操作、详情与返回可访问。有缺陷只修相关布局和相机取景。
5. 记录需求编号、复现、根因、最小修复、复测。不得移动/缩放/旋转模型根节点，不修改原GLB/manifest/registry，不把身份假设改成已核实。
6. 不接火势/无人机/电网/应急/登录/后端，不删兼容显示。模拟告警目前未启用，不给未知火情标安全。

Plan先输出工程识别、文档与实现差异、运行条件、待测项、最小计划。等我切换实施模式后执行。

交付：修改文件列表、需求对应、命令退出结果、浏览器型号/视口/渲染模式、关键截图、剩余未验证项、git diff --check。未运行写未运行，禁止编造通过。

先不git push、不部署阿里云、不改已有域名。本地验收后再安排远程仓库与部署。
```

完成后给本对话：CodeBuddy总结、关键截图、终端结果；有改动附源码ZIP（排除node_modules/.git/凭据）或diff。此对话验收后再安排下一轮提示词。
